# App 业务管理示例版实施计划

> 使用 executing-plans 在当前管理后台分支连续实施，最后进行一次独立复查。

## 目标和设计

完成业务总览及 App 用户、饮食、抽烟、运动、AI 用量五个管理页面。沿用 Cool Admin CRUD 和权限系统，以独立 diary 模块、独立业务表和显式示例标记管理合成数据。用户已要求直接开发、编译，网站交互验收由用户完成。

App 用户支持资料新增、修改和启停用，业务记录支持筛选、分页、详情及新增修改删除。AI 用量作为请求日志提供筛选和详情。总览统一展示日期范围内的汇总和趋势。

## 数据约定

- 数据来自本次生成的合成示例和后台手动维护，均标记为示例。
- App 用户表独立于框架管理员及框架模板用户表。
- 饮食保存餐次、来源、热量和三大营养素。
- 抽烟区分自吸和赠出，尼古丁为包装标注累计值，赠出不计入自吸统计。未知标注保留为空。
- 运动保存类型、距离、时长、消耗、平均和最高心率，可保留未知心率。
- AI 记录功能类型、模型、状态、输入输出与缓存 tokens、时延、预估费用及失败原因。缓存 tokens 属于输入 tokens 的子集。
- 所有业务日期用北京时间字符串保存，区间包含所选起止日期。
- 私密配置沿用现有环境文件，演示种子采用事务和幂等标记。

## 文件与步骤

### 1. 数据模型、校验与接口

- 新建 backend/src/modules/diary/entity 下五个实体和公共基类。
- 新建 dto/record.ts，集中白名单、必填项、枚举、范围、日期和派生统计计算。
- 新建 service/management.ts 和 controller/admin 下各资源控制器。
- 复用 Cool Admin page/info/delete，写入使用验证后的字段，禁止通过未知字段修改系统属性。
- 回归检查覆盖赠烟、未知标注、零值、非法范围、AI 缓存 tokens 和关联用户。

### 2. 页面和权限

- 新建 frontend/src/modules/diary，复用列表表格、编辑表单和详情抽屉。
- 增加业务总览、用户、饮食、抽烟、运动、AI 用量菜单及权限。
- 各记录页提供用户、日期、业务类型筛选和对应汇总。
- 用户详情展示关联记录汇总及跳转，统一显式示例数据标识。

### 3. 示例、文档与编译

- 新增显式 seed 命令，事务生成关联用户及多日业务示例，重复执行保留编辑结果。
- 更新管理后台说明及首页入口。
- 执行后端编译、前端类型检查及打包、必要单元与接口检查。
- 页面交互和视觉验收交由用户，完成后记录编译和数据数量。

## 复查重点

- 更新必须合并已有记录后校验，不能通过缺省字段覆盖关联或派生值。
- 自吸和赠出分开汇总，未知尼古丁与未知心率保持未知。
- 日期、用户筛选与汇总口径一致，非法条件需要被拒绝。
- 示例插入失败回滚，重试和并发执行不重复插入。
- 权限菜单的读写能力与实际 API 一致，所有业务接口均需后台身份。
