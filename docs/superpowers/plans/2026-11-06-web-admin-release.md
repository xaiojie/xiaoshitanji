# 官网与管理后台独立发布

> 使用 executing-plans 连续实施，发布前完成独立复查。

## 已授权目标

将现有 site 官网发布到域名根路径，将 Cool Admin 发布到 /admin/，管理接口使用 /admin-api/。审核中的 App 使用现有 FastAPI 服务及其注册接口，发布中保护对应请求路由、请求头、限制、超时和审核文档。

## 实施步骤

1. 保存线上 Nginx、审核文档校验值、App 容器标识与源文件校验值，形成回滚材料。
2. 适配后台 /admin/ 构建路径、图标、接口前缀和线上上传地址。提供独立容器的生产配置，关闭自动建表和初始化。
3. 在 Mac 生成后台正式构建、前端静态产物和官网运行素材。部署包排除环境文件、开发依赖、原型图与设计文档。
4. 在服务器构建并启动独立 Midway 容器，连接已有 MySQL 示例库，使用新生成的生产会话密钥。先在服务器回环地址验证登录与查询。
5. 部署版本化官网及后台静态目录，校验 Nginx 配置后平滑重载。
6. 检查官网、后台资源和深层路由、管理登录与查询、App 接口、AI 转发、隐私和支持页。记录发布版本与回滚步骤。

## 路由约定

- /v1/、/healthz、/openapi.json 明确指向当前 127.0.0.1:8787。
- /privacy、/support 使用现有独立审核文档目录。
- /admin/ 提供后台静态产物，SPA 回退仅限该路径。
- /admin-api/ 去掉外层前缀后转发至独立 127.0.0.1:8002。
- / 提供官网运行文件，未知路径返回 404。

## 验收边界

- 核对 App 容器启动时间、镜像及源码校验值，审核文档内容校验值。
- 以相同注册接口定义和关键响应检查路由兼容，AI 使用合成短文本做发布前后检查。
- 管理后台连接示例数据，生产配置关闭 schema 同步及种子自动导入。
- 构建、服务与接口检查由本次执行，网站视觉与操作验收沿用用户自行测试的安排。
- 新管理服务设置资源上限，MySQL 使用已有独立实例。
