# 子页面修复与汇总分析

用户要求修复遗漏的新样式和 UI 问题，在「我的」加入跨饮食、抽烟、身体与运动的汇总分析。用户明确选择默认近7天，可切换近30天和全部记录。延续已授权的直接开发方式，在现有原生 SwiftUI 与 DeepSeek 接口上实施。

## 界面与问题

截图中的设置页仍是白色系统 Form，标题与主界面不一致。改为黄色品牌头部、奶油分组卡和明确的保存按钮，同时适配资料、体重和分烟表单。Composer 把 confirmationDialog 挂在整个滚动页面，系统将其显示为顶部气泡，改为居中 alert 并明确保留继续编辑。已选照片的虚线 reticle 会压住图像内容，预览改成有边界的完整图片容器。

## 分析范围

「我的」资料卡下方提供汇总分析入口。默认7天，支持30天和全部记录。全部记录以本机及可读取健康数据最早日期为起点。四类数据使用同一日期区间，身体测量展示最近一次的日期和来源，体重变化仅在范围内有至少两次不同时间测量时计算。

本地计算餐数、记录天数、营养总值与记录日均值，自己抽的数量、分烟数量、包装标注累计和各币种费用，活动总值及各项实际有数据天数，身高、最近体重、BMI、目标体重。无数据保留缺失，活动能量仅指活动部分，分烟和库存校准排除个人摄入。输入按日或月汇总，历史照片、头像、昵称、原始描述不进入此请求。

## AI 与保存

复用 DeepSeek 请求和网络处理，输出总览、四类观察、三项优先行动和数据局限。生成前展示范围和将发送的字段，用户在应用内确认发送健康汇总后调用。可关闭健康数据，只分析本机记录。读取失败可重试，或关掉健康后生成。模型区分缺失和零，禁止推断未记录饮食或吸烟，禁止把包装烟碱当成实际吸收，禁止用活动能量计算全天热量缺口。

最近一次各范围的报告和汇总数值保存在本机，随导出 JSON 一并导出。旧文件缺失新字段时默认空。报告标明生成时间与数据截止时间，新报告请求失败保留旧报告。保存基于当前文档副本，不覆盖生成期间的其他记录修改。

## 验证

新增针对跨日聚合、缺失、分烟排除、历史范围、体重测量来源、请求隐私、响应格式与旧格式回读的回归测试。完整套件、真机 Debug/Release 构建、签名和真机安装。仅使用实体 iPhone。完整交互或截图仍受连接限制时明确记录实际已验证范围。
