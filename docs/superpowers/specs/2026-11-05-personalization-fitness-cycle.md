# 个性化档案、健身入口与经期跟踪

> 记录日期：2026-11-05。状态：方向已确认，纳入后续待完成项目，尚未开发。
> 当前优先事项：1.0.1（37）的 App Store 上架。本方案不进入当前审核包。
> 1.1.0 / 1.2.0 是建议的阶段版本号，具体发版时间后续排定。

## 目标与现有基础

把应用从个人饮食与吸烟日记，逐步扩展成按用户目标组织的健康记录工具。用户愿意提供的信息、实际记录、启用模块和本次授权范围共同决定建议；未提供的信息保持未知。

当前已实现饮食、吸烟、个人资料、能量目标、训练记录、训练计划、Apple 健康读取、汇总分析及自由追问。新增健身首页复用已有训练能力；首次引导、动态模块、跨入口个性化和经期跟踪属于本轮新增待办。

技术沿用 SwiftUI、NutritionCore、本机 JSON、可选云同步与后端 DeepSeek 服务。延续黄色奶蛙视觉、自然语言和拍照记餐，不增加食品逐项称重要求。

## 方案选择

| 方案 | 取舍 |
| --- | --- |
| 按性别固定切换戒烟与经期 | 实现简单，但无法覆盖女性吸烟、同时需要两类记录、不愿透露性别等情况，不采用 |
| 独立模块开关，分阶段交付 | 性别只影响初始推荐，功能由用户确认；复用现有训练记录，先打通档案与分析，再加入经期，采用此方案 |
| 所有能力在一次更新中完成 | 测试与迁移范围大，会推迟下一版交付，暂不采用 |

本次仅落地方案文档和任务登记，不修改应用功能，不进行新的 Apple 上传或提审操作。

## 首次引导与资料编辑

进入应用的首次引导控制为三步，可逐项跳过，也可整体选择稍后设置。离线可完成，不要求创建账号。

| 步骤 | 内容 | 规则 |
| --- | --- | --- |
| 了解你 | 性别、年龄，均有“不愿透露” | 区分未填写、主动不透露和已填写；不使用默认男性或默认出生年份代替用户输入 |
| 你的目标 | 减脂、增肌、保持体重、提高体能、先记录看看 | 一个主要目标；戒烟、经期跟踪等作为独立偏好 |
| 你的记录方式 | 是否记录吸烟、是否需要经期跟踪；身高体重可选 | 根据确认结果配置模块；支持稍后从“我的”修改 |

- 年龄不要求提供完整生日，记录填写时间，支持更新和清除。现有能量计算需要的参数必须经确认，不能由未填写年龄推断出生年份。
- 健身偏好、训练经验、每周可训练次数在首次进入健身时补充，避免初次打开填表过长。
- Apple 健康、相机、麦克风、通知等按对应功能实际使用时申请，不集中在引导中索取权限。
- 信息不足时提供一般记录与建议；需要年龄或生理参数的公式不生成虚假的精确目标。生理参数的用途与个人展示信息分别说明。
- 继续沿用当前协议的成年人产品定位；未成年人支持不在本次范围。不愿透露年龄不等同于已确认年龄。
- 用户可在“我的 → 个人资料 / 目标与模块”重新设置；更改目标不会改写历史记录和当时的目标快照。

## 模块与导航

健身固定放在趋势后面。吸烟记录与经期跟踪为独立开关，性别只提供初始推荐，不能直接证明某种习惯或身体状态。

- 男性：询问是否需要记录吸烟，由用户选择开启或关闭。
- 女性：初始推荐不记录吸烟，推荐经期跟踪；两项均需用户确认，也可同时开启。
- 不愿透露或未填写：提供中性的模块选择，不推断是否吸烟或是否有经期。
- 推荐项尚未确认时，不创建相应记录、不宣称用户有对应习惯、不申请经期相关权限。

| 已启用模块 | 底部导航 |
| --- | --- |
| 两项均关闭 | 饮食 → 趋势 → 健身 → 我的 |
| 仅吸烟 | 饮食 → 趋势 → 健身 → 戒烟 → 我的 |
| 仅经期 | 饮食 → 趋势 → 健身 → 经期 → 我的 |
| 两项均开启 | 饮食 → 趋势 → 健身 → 健康习惯 → 我的；健康习惯内切换两类记录 |

关闭模块的效果必须同时覆盖页面入口、趋势图、自动观察、汇总分析、自由追问和新生成报告。关闭吸烟后不再注入吸烟统计，也不提示“缺少吸烟记录”。

关闭与删除分开：关闭保留历史，可重新启用；彻底删除须单独确认。用户仍能管理自己的历史与备份。旧报告保留生成时的范围标记，但关闭模块后不得作为新分析上下文或继续主动推荐。用户在自由文本中自行提及某类内容，不等于授权读取该模块的历史。

## 所有 AI 入口使用一致的个人信息与范围规则

共享上下文按功能取最少必要内容：用户明确提供的档案、当前目标、数据时间范围与来源、已启用模块、授权范围、记录完整程度。共享规则不意味着每次识别都发送完整健康档案。

| 入口 | 事实处理 | 个性化建议 |
| --- | --- | --- |
| 餐食与营养表识别、续改 | 根据食品、标签、实际份量计算；不因性别或目标改变营养事实 | 结合已确认目标、当日记录给出份量与搭配建议，估算后仍需确认保存 |
| 烟盒识别 | 名称、包装标注、价格按可读信息处理 | 仅模块开启且有相应授权时关联习惯建议 |
| 每日回顾 | 使用当天真实记录和记录完整程度 | 结合当前目标与适用资料，不对缺失记录编造结论 |
| 汇总与自由追问 | 使用近7天、近30天或全部的同一范围与证据 | 按启用模块提供饮食、训练、恢复及可选经期的综合建议 |
| 健身建议 | 使用真实训练、活动与恢复数据，明确来源 | 区分增肌、减脂、维持、提高体能等目标 |

- 营养标签、库存、费用、BMI、训练容量等确定性数值由本地逻辑计算或校验，AI 负责解读与建议。
- 日期、测量新旧、记录日数、缺失项必须可见；无记录不等于数值为零，也不等于用户没有某种习惯。
- 资料、目标、模块、授权和记录变化必须进入报告快照与缓存有效性判断；旧报告标记基于此前资料，不自动改写。
- 请求发出前再次检查当前范围；等待中的请求遇到撤权或关闭模块应取消，迟到的响应不得按新范围保存或展示。
- 用户选择不提供性别或年龄时，分析仍可继续，但不猜测资料，不使用不适用的代谢公式。
- Apple 健康汇总维持现有逐次范围确认，首次 AI 数据授权与撤回机制继续生效。

## 健身首页

复用现有 WorkoutRecord、WorkoutPlan、WorkoutLogView、WorkoutEditorView 和 HealthKit 数据，不另起一套训练记录。

首版提供今日训练、开始记录、常用计划、最近训练与周趋势。力量记录动作、组数、次数和重量；有氧记录项目、时长和距离，心率与体感可选。训练偏好在需要时补充。

训练来源明确区分 Apple 健康和手动记录，复用现有健康训练优先的消耗口径，避免同一场训练重复计数。AI 先提供可执行的饮食搭配、训练频率与恢复建议；复杂自动训练计划和动作识别后置。

## 经期跟踪

首版能力：经期开始与结束日期、日历、历史周期，可选记录经量、疼痛、情绪和精力，以及用户主动设置的提醒。

- 先记录，再分析。区分用户记录与预计日期，不自动把预测写成已发生的经期。
- 数据足够后展示有不确定范围的预计日期；资料不足或周期不规律时降低预测强度并说明原因。
- 精确预测窗口、样本阈值和算法在该阶段开发前单独确认并验证，不把当前规划当成医学模型。
- 不根据性别推断经期，不提供疾病诊断、避孕判断或确定的排卵结论。
- AI 可结合实际症状、体重短期波动、睡眠和训练体感提供日常建议，不强制用户按预测周期调整训练。
- 本机记录、用于 AI、进入云同步分别说明并由用户选择；拒绝后仍能使用不依赖该选择的功能。
- 支持查看、修改、删除、导出与关闭；通知内容默认避免在锁屏暴露敏感细节。

## 旧用户与数据迁移

- 老用户不强制重新填写引导；以可跳过的补充资料入口出现。
- 已有吸烟记录的用户保留原入口，提示确认偏好，避免升级后误以为历史丢失。
- 旧能量设置可预填供用户确认，但初始化默认值不能自动变成已确认的个人档案。
- 当前数据 schema 为 5；新增档案状态、模块选择与经期记录时需制定新版本迁移，支持旧文件、完整备份及云端历史。
- 同步后端先支持新 schema，再发布对应客户端；旧客户端应明确拒绝不支持的高版本，避免重写时丢失新字段。
- 新敏感字段的同步过滤必须同时覆盖照片/快照、历史恢复和冲突合并，不能只过滤 AI 请求。
- 迁移失败保留原文件和保护副本，不以空文档覆盖；关闭模块不得触发历史删除。
