# 同步与备份完整性修复

用户要求解决本次状态核查列出的全部问题。当前基线 feature/backlog-v1 e260c8f，工程1.0(30)。已有未提交的-tab启动辅助与SeedFixtureTests由本轮整理为显式开发工具。

## 实施决策

服务端兼容schema1–5并拒绝未知版本。外置照片采用用户隔离的独立二进制传输，以SHA256内容名保存不可变图片，快照仍受8MB限制。先上传缺失照片，再提交日记快照，读取快照时先取齐照片再写本机。服务端拒绝引用未上传图片的快照。同名重复上传幂等，失败重试复用已有内容，历史版本继续引用原图片。

备份与JSON导出生成带图片内容的自包含文件，恢复保留旧格式兼容。缺少源图片时报明确错误，避免生成不完整备份。现有仅含文件名的备份可在原Photos目录仍可用时补全。恢复前保留本机快照并由用户在App中确认。

冲突合并覆盖workouts、plans并保持本机同ID优先，修复首次登录同步覆盖云端已有记录的问题。其他记录语义沿用保守并集合并。

整理截图辅助为Debug/显式环境开关，修复编译警告，统一工程、README、backlog的版本和实测状态。签名构建iPhone主程序和小组件。核验已有线上服务和TestFlight状态，部署所需访问缺失时列出精确限制，不把本地测试当成上线证明。

## 验证

失败测试先覆盖schema5、照片鉴权/哈希/幂等/缺失、训练合并、照片备份与恢复、缺失文件和首次同步。完整Swift与服务端测试、iPhone Debug/Release签名和构建验证。仅实体iPhone，已由用户选择自行进行界面测试。
