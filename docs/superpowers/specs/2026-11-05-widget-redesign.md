# 奶蛙今日摄入组件

> 2026-11-05，用户已确认小号与中号原型并要求开发；“记一餐”必须直接进入餐食录入页。
> 范围：小号 / 中号桌面组件、必要的快照数据与 App 跳转。当前 1.0.1（37）审核由用户处理，不上传、不撤回、不替换审核构建。

## 视觉目标

- [小号原型](../../design/widgets/small-prototype.png)：方形黄色渐变、奶油白分组、深棕色圆角数字，奶蛙上半身陪伴今日摄入。
- [中号原型](../../design/widgets/medium-prototype.png)：同一套视觉，左侧营养与目标，右侧完整奶蛙和“记一餐”；底部补充各餐次。
- 使用项目已存在的奶蛙透明 PNG 和系统叶片 / 火焰 / 水滴图标，不把原型整张图作为组件背景，文字与数值均为真实控件。
- 小号按约 170 × 170 pt，中号约 364 × 170 pt 设计，并适配系统实际提供的尺寸。文字不能与奶蛙重叠，数值支持缩放与辅助阅读。

## 数据与状态

- 两种尺寸：今日摄入、餐数、剩余热量、有限范围的目标进度、三大营养素。
- 中号增加：目标值、更新时间、早餐 / 午餐 / 晚餐 / 加餐的已记热量或待记状态。
- 所有数值来自本机当日记录。原型中的 566 / 1,800 / 1,234 仅为演示，不写入用户资料。
- 未设置目标时显示“未设置目标”，不补默认目标或虚构剩余值；无记录时显示今天待记录。
- 兼容旧组件 JSON；缺少餐次分项时保持未知，不能把旧快照显示为每餐均未记。
- 跨自然日不继续显示昨天数字，时间线在下一个本地零点切换为今日待更新状态；普通刷新仍受 WidgetKit 调度约束。
- 目标口径与 App 今日页一致：优先能量预算及当天有效训练消耗，否则使用用户设置的参考目标。
- 保存、修改、删除、恢复记录与目标变化后刷新；健康数据和回到前台、跨天后也更新今日快照。

## 直接记餐

- 中号主按钮使用专用 URL，冷启动或从后台返回都切换到饮食页，直接展示现有 ComposerView。
- 自动选择点击时刻对应餐次，沿用既有预设餐次时间；用户仍可修改餐次和日期。
- 点击组件其他区域进入今日饮食，不能停留在此前浏览的历史日期。
- 待处理跳转只消费一次；未知 URL 不触发记餐。
- 现有表单或未保存草稿不被强行替换，待其正常关闭后处理记餐请求。日记读取失败时不创建可覆盖数据的空白编辑流程。
- 跳转本身不拍照、不提交 AI、不保存空记录，也不改变 AI 授权和确认后保存边界。
